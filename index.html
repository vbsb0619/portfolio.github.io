Where the pipeline starts

I started as a co-founder — setting up machines, writing the first lines of code, and hiring the first engineers for a real-estate operations startup before I'd even finished my undergrad degree. That instinct to build the whole thing, not just my corner of it, has stuck with me through 16 years spanning startup leadership, enterprise database administration, cloud migrations, and now large-scale ETL architecture — the last 10+ of them focused specifically on data and database engineering.

Today I design and operate the pipelines that keep loan, payment, and CRM data flowing accurately across origination, servicing, and finance systems for a national mortgage & financial services platform — processing thousands of loans and 1,000+ dealer invoices every cycle, without anyone downstream noticing the machinery underneath.

What I care about isn't just moving data — it's making pipelines that fail safely, alert early, and recover on their own.

Case studies

Selected production systems I designed, built, and kept running. Click to expand.

Problem

Dealer invoicing and payment reconciliation between the loan accounting system and Stripe was manual, error-prone, and couldn't scale with 1,000+ retail dealers billed every month.

What I built
  • Architected 20+ database objects — tables, stored procedures, and functions for invoice generation, payment sync, and reconciliation
  • Built a JSON payload engine using PostgreSQL's jsonb_agg/json_build_object to support dynamic, per-dealer line items
  • Designed fee-calculation business logic (capped ACH fees, tiered software fees) and a Finance-controlled override to pause specific invoices from syncing
  • Diagnosed and fixed a production bug where an UPDATE ordering issue was silently zeroing out processing fees during credit invoice generation
Impact

Runs monthly invoicing for 1,000+ dealers with automated reconciliation, including edge cases like partial payments, manual credit memos, and out-of-band Stripe adjustments.

Problem

The pipelines feeding contact-center analytics for originations and servicing teams failed regularly due to integer overflow from legacy data references, taking down entire jobs over single bad records.

What I built
  • Diagnosed the overflow pattern and built a repeatable fix: null out invalid records in temp tables, then re-run merge procedures
  • Led removal of the legacy field references causing the recurring failures, eliminating the root cause
  • Designed error-catch logic so the pipeline processes all valid records even when individual rows fail — no more full-job failures from one bad record
  • Ran discovery to right-size the data lookback window, balancing completeness against performance
Impact

Converted a chronically unstable pipeline into a reliable daily feed for two business teams.

Problem

Incoming credit application documents needed automated capture, classification, and routing — with visibility into where and why documents failed classification.

What I built
  • Built Power Automate flows for email monitoring, PDF extraction, SharePoint storage, and calls into a Lambda-based OCR classification engine
  • Added timeout (5 min) and retry logic (3 attempts) on Lambda calls to prevent queue buildup, plus PDF-only filtering to block bad attachments
  • Added structured error logging for "unknown document type" and "missing PDF" cases, then modularized the flow into high- and low-fidelity paths
Impact

Turned an opaque failure mode into a measurable, reportable process — with dealer-level misclassification analysis feeding ongoing OCR accuracy improvements.

Problem

Legacy SSIS + ad-hoc Python scripts didn't scale as an ETL standard — no shared framework, inconsistent deployment, and no unified monitoring across environments.

What I built
  • Helped build the core framework's class library architecture (Identity → Parameter → Task → Stage → Pipeline) that every job now standardizes on, running in Docker containers on AWS ECS with Jenkins CI/CD across DEV → UAT → QA → PROD
  • Built 25+ production pipelines on this framework, including a loan-monitoring system that reconciles the origination system against the data warehouse daily, government economic-data ingestion for a loss-severity model, a legacy mainframe file parser, and multiple vendor finance-report integrations built from scratch
  • Refactored a 7-job pipeline chain into a single parent-child orchestrated Jenkins pipeline with proper dependency management
  • Led an org-wide inventory of every active pipeline on the framework to plan and coordinate shared-library upgrades
Impact

Became the team's default ETL standard — 25+ full pipelines and 15+ lightweight jobs now run on it in production.
